# Checklist · feat(llm): porter le statut HTTP sur LLMError · #34

Issue : https://github.com/arthurolivierfortin/agent-core/issues/34
Spécification : docs/specs/2026-09-30-llm-error-status-design.md

## Livrables
- [x] [SPEC-1] Élargir le troisième paramètre du constructeur de `LLMError` à `options?: { cause?: unknown; status?: number; retryAfterMs?: number }` (type en ligne, aucun nouveau nom exporté), déclarer `declare readonly status?: number;` et `declare readonly retryAfterMs?: number;` (jamais sans `declare`, pour qu'aucune propriété `undefined` ne soit définie sous `useDefineForClassFields`), garder `super(message, options)`, puis poser `this.status = options.status` si `options?.status !== undefined` et `this.retryAfterMs = options.retryAfterMs` si `options?.retryAfterMs !== undefined`, et compléter le TSDoc de la classe (deux champs numériques, jamais des chaînes ; `status` posé seulement par un fournisseur qui le rapporte, aujourd'hui `GeminiLLMProvider` sur toute erreur d'une réponse non ok ; son absence ne dit pas que l'échec n'était pas HTTP), `LLMErrorCode` restant inchangé — fichier attendu : src/llm/models/index.ts
- [ ] [SPEC-2] Poser `status: res.status` sur toute `LLMError` levée pour une réponse non ok : ajouter à `readBody` le troisième paramètre facultatif `http?: { status: number; retryAfterMs?: number }`, passé tel quel en options de son `new LLMError("API_ERROR", "Gemini <res.status> response body could not be read: …", http)` (message inchangé, appel du chemin ok sans `http`) ; dans `httpError(res, url, model, apiKey)`, construire `const http = { status: res.status }` en première instruction, appeler `readBody(res, apiKey, http)` et passer `http` en troisième argument aux trois `new LLMError(...)` (`MODEL_NOT_FOUND` du 404 `NOT_FOUND`, `API_ERROR` des autres 404, `API_ERROR` des autres statuts), messages inchangés au caractère près, aucune autre `LLMError` du module ne recevant `status` ; ajouter à l'en-tête du module la ligne `// HTTP status (#34): docs/specs/2026-09-30-llm-error-status-design.md. Every LLMError of a non-ok response carries status, even when its body cannot be read; a network failure or an ok response carries none.` — fichier attendu : src/llm/providers/gemini/gemini-llm-provider.ts
- [ ] [SPEC-3] Ajouter la fonction de module non exportée `retryAfterMsOf(res: Response): number | undefined` qui lit `res.headers.get("retry-after")`, rend `undefined` si l'en-tête est absent, si sa valeur passée par `trim()` ne correspond pas à `/^\d+$/`, ou si `Number(value) * 1000` n'est pas un entier sûr (`Number.isSafeInteger`), et sinon rend `Number(value) * 1000`, sans jamais lever ni citer la valeur brute ; dans `httpError`, étendre `http`, toujours construit avant `readBody`, en `{ status: res.status, retryAfterMs: retryAfterMsOf(res) }`, ce qui le porte aussi sur l'erreur d'un corps d'erreur illisible ; ajouter à l'en-tête du module la ligne `// retryAfterMs comes from a Retry-After in delay-seconds form only (H9).` — fichier attendu : src/llm/providers/gemini/gemini-llm-provider.ts
